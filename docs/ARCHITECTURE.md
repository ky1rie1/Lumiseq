# 架构与模块边界

Lumiseq 使用 React 19、TypeScript、Zustand、Tauri 2 与 Rust。桌面界面、内置 AI 和外部 MCP 使用现有文档与命令系统协作。

工作区调用 `app / edit / develop` 操作服务；AI Provider 经 `AgentRuntime` 调用 `ai/tools` 规范工具，MCP 经 `AgentBridge` 调用同一工具目录。规范工具可以调用操作服务或直接创建专项命令；文档写操作通过 `history / CommandBus` 执行，再更新 `document / DocumentManager`。

渲染、资源管理与项目存储消费文档状态；资源读取与图像处理经 `platform` 接入 Tauri / Rust。图中展示主要依赖层级，任务观察与复核的返回路径见下文。

文档是可保存的编辑状态；Zustand 管理界面与工作区状态。渲染缓存、显示 URL 和原生像素资源不应被当作项目状态复制。

## 模块职责

| 模块 | 职责与入口 |
| --- | --- |
| `src/ui/` | 首页、图像编辑、照片调色、设置与共享控件 |
| `src/app/` | 打开文件、保存工程、PSD、导出、最近项目与关闭流程 |
| `src/document/`、`src/types/` | 文档工厂、递归图层、接口与参数结构 |
| `src/commands/`、`src/history/` | 可撤销操作、事务和历史；专项命令也位于 brush、mask、selection 等模块 |
| `src/engine/` | WebGL 调色预览、版本化 Float32 分块图层合成、变换、蒙版与直方图；旧工程保留 Canvas 合成 |
| `src/filters/`、`src/smartobject/` | 智能对象滤镜计算与对象转换 |
| `src/develop/` | RAW 操作服务、预设、自动影调和预览调度 |
| `src/edit/` | 图层树、祖先锁定策略、复制与几何操作服务 |
| `src/cutout/` | 固定模型校验、Worker 推理、精修与蒙版应用 |
| `src/ai/` | Provider、能力路由、AgentRuntime、权限、规范工具与 MCP |
| `src/platform/` | 原生能力接口与 Tauri 实现 |
| `src-tauri/src/` | 文件、剪贴板、DPAPI、MCP、本地 RAW 资源与导出 |
| `src-tauri/native/libraw/` | 第三方 RAW 解码源码、头文件及构建静态库 |

`src/ai/tools/ToolRegistry.ts` 是当前 AI 的规范工具入口。`src/tools/` 同时包含画布数学工具与早期工具接口；早期接口仍被回归测试引用，新增 AI 功能接入规范工具注册表。

## 文档和资源

- `EditDocument` 保存图层树、选区、裁剪和编辑元数据。
- `DevelopDocument` 保存 RAW 来源、调色参数、局部蒙版、快照和 AI 记录。
- `DocumentManager` 管理打开文档、活动文档和更新事件。
- `AssetManager` 管理图像 Blob、蒙版、显示 URL 与原生资源引用。
- 原生 RAW 像素由 Rust 资源注册表持有，预览按需获取。新 RAW 的主缓冲为扩展范围线性 sRGB RGBA32F，保留负值和高光余量；旧解码版本保持原有解释。边界见 [RAW 质量](RAW_QUALITY.md)。

### 图像编辑精度与工程格式

新图像工程显式声明 `renderingVersion: 2`、`bitDepth: 32`、`workingProfile: 'linear-srgb'`。原文件 Blob 与参数构成可重放状态；Rust 的 ICC 感知解码器提供有界 LF32 区域，`engine/editFloat` 进行浮点调整、滤镜及分组／蒙版合成，最后才缩放和转换为屏幕或交付编码。原素材的实际位深与浮点工作精度分别报告。

`LSQ2` 工程把有界 JSON 清单与原始二进制资源分开，校验偏移、资源引用及 SHA-256 后再注册资源。它保存原始 RAW／栅格、蒙版和参数，不保存派生的全尺寸浮点缓存。旧 JSON 工程继续使用原有渲染；显式升级产生独立副本。高精度工程不能通过当前 8 位 PSD 写入器静默降级，使用 `.lsq` 保存可编辑状态或 PNG16／TIFF16 交付。

RAW 转入编辑器形成真正的 `develop-smart-object`：保存原始文件与调色配方，参数编辑在关联 Develop 文档中进行，通过命令一次应用、一次撤销。关闭文档释放其解码租约；共享原文件与历史使用的不可变 Blob 保留。原生 RAW 分块配方使用有界行缓存，同一配方的相邻列复用计算。具体合同见 [编辑精度](technical/EDIT_PRECISION.md)。

## 命令、历史与 AI

改变文档的编辑功能应有对应 `ICommand`，通过 `CommandBus` 执行。连续拖动和画笔使用事务或合并机制。AI 工具调用相同命令，返回命令 ID、文档 ID、结果与明确错误，避免直接写界面状态来模拟编辑。

操作服务接受文档管理器、命令总线和资源管理器依赖。AI 写操作注入当前任务所属的总线，使权限、事务和整组撤销保留原有归属；不能在工具内部使用全局总线绕过任务上下文。

### 图层树与资源

图层操作按树中的父组定位；继承祖先锁定，内容写入在命令入口校验。可见性和界面选择属于允许操作。复制递归创建新的图层、蒙版与滤镜标识，资源引用可以共享不可变素材；后续像素修改注册新资源。对齐采用文档坐标中的实际边界，翻转保留显示中心，父组变换参与计算。

分组展开与焦点保留在界面状态中，不写入工程脏状态。新增控件使用 `unified-theme.css` 的颜色和运动 token；照片、通道和蒙版数据保持各自语义颜色。

### 曲线与参数剪贴板

曲线坐标辅助只负责 CSS 坐标、节点命中与数值边界；React 控件负责指针捕获及键盘生命周期。`DevelopOperationService` 使用已有 `CommandBus` 事务合并预览，并持有实际事务 token，避免旧控件清理影响后续操作。一次连续操作产生一个历史步骤，取消恢复初始参数。渲染和导出继续消费文档中的相同归一化曲线。

`DevelopSettingsClipboard` 是有界、可序列化的会话状态，保存参数清单、来源和复制时间，不保存素材、局部蒙版或相机矩阵。UI 与规范工具共用默认实例，也支持测试注入。粘贴在校验及目标白平衡解析完成后提交一个命令；工程存储不包含这个临时剪贴板。

Provider schema adapters 把规范工具转换为各服务的 function calling 和 MCP schema。能力路由与权限策略位于 AI 层，像素算法位于编辑或原生层。

本机 Agent 通过 `LocalAgentProvider` 使用同一 `IAIProvider` 接口，Tauri 的 `commands/local_agents.rs` 负责客户端发现、进程生命周期与有界输入输出。Agent 沿用自己的模型服务和登录配置，返回的请求继续经过规范工具、权限与命令历史；应用内聊天和反向 MCP 共用编辑能力。

运行时在模型回复和命令执行前检查文档是否仍有效；手动编辑或切换文档使旧请求停止。由 Agent 明确创建或激活的文档会更新本轮工具目录与上下文。

### 文档观察与图像通道

`src/ai/vision/DocumentObservationService.ts` 从指定文档的版本化状态生成整图、区域和原尺寸细节，复用现有 `WebGLImageEngine`。它拥有独立的渲染实例与有界缓存，不读取界面画布，也不改变用户视口。版本 2 编辑合成使用原尺寸分块及有界缩放缓存；旧版本的某些分组／调整仍需完整文档中间缓冲，缓存上限不代表全部渲染工作内存上限。

每张观察包含实际源尺寸、区域、输出尺寸和原文档坐标映射。服务在渲染前后检查版本；过期结果拒绝使用。RAW 区域读取携带原管线所需的边界像素及全局分析，细节输出保持 1:1。资源清理只释放观察服务拥有的资源，共享源素材继续有效。

`AgentMessage.images` 和 `ToolResult.images` 承载临时图像，证据元数据与图像正文分离。Provider serializers 将图像转换到服务的原生多模态结构，MCP 返回标准图像内容块。共享输入校验限制数量、MIME、解码字节与完整请求体大小；超过限制会拒绝并要求减少或缩小观察，不静默改变对应坐标。

本地 Agent 的图像通过任务独占目录中的固定名称只读文件传入，参数按独立 argv 传递。原生层保留进程取消、超时与有界输出；进程及子进程退出后才释放附件。实际图像接口需探测，当前模型是否理解图像另行验收。连接能力与上传授权由现有能力路由决定。

观察是 sRGB 显示证据，数值色准使用像素取样或独立测量。模型主观评价、协议测试和真实色卡测量分别记录，不能相互替代。

### 任务调用与复核

`src/ai/harness/` 提供每次任务的操作指南、任务策略、预算和结果复核，执行仍由原有 `AgentRuntime` 与任务所属的 `CommandBus` 完成。精确参数操作读取实际状态；摄影、局部细节和排版任务分别要求相关图像证据。尺寸或参数出现在审美请求中时，仍需保留视觉检查。

观察采用整图概览、原文档坐标区域和 1:1 细节的顺序；局部编辑必须将修改范围与已观察目标对应。修改前完整合成作为临时基线保留，修改后重新渲染，同坐标区域及相邻边缘进入独立上下文复核。文字连接通过已配置视觉后备取得与当前版本对应的描述。

工具成功、实际状态验证和主观审美结论分别记录。预算耗尽或证据不足保留部分完成状态；任务记录只保存精简事实、图像证据引用与覆盖范围。取消和超时信号需要传至观察服务，阻止结束任务后发布迟到图像。旧画布快照 API 保留兼容用途，任务视觉证据读取文档渲染。

### 创作方案与用户偏好

`CreativeBrief` 按任务保留摄影或排版的目标、内容约束与参考来源。`CandidateService` 使用独立 `DocumentManager` 和 `CommandBus`，通过同一规范工具与渲染引擎生成至多两个方向。原素材以只读引用共享；保存、导出与外部生成不进入候选重放路径。

方案保留规范操作和新对象符号引用。接受方案时重新核对源文档、选择、锁定及权限，再以原任务归属重放命令；不向模型重新索取另一份操作。取消或放弃释放服务拥有的候选资源，后续手动编辑仍受原历史保护。

接受过程进入同一活动任务生命周期，权限与工具等待使用原任务预算和取消信号，结束及安全回滚后才允许新任务。技术复核只检查实际接受的命令；用户选中方向是审美反馈，不清空文字溢出等技术问题。参考图在准备前检查预算，保留的像素和来源以临时、分离的副本进入独立复核，不写入工程图像正文。本机连接只传输原生允许的附件字段。

`TastePreferences` 保存用户明确提交的摄影／排版偏好；模型评价不写入。`CreativeReview`、聊天与连接设置共享存储入口，偏好不改变图像工程的未保存状态。创作工具通过规范注册表同时提供给内部运行时与 MCP。

## 新能力接入顺序

1. 在 `types/` 定义可序列化的数据和有效参数范围。
2. 实现计算逻辑与可撤销命令，验证错误及资源边界。
3. 接入预览、导出和项目保存；确认旧工程兼容性。
4. 在工作区或属性面板提供控件。
5. 注册规范 AI 工具、schema 和 MCP 名称映射。
6. 验证撤销、重开工程、实际图像结果与独立程序。

智能滤镜是这一流程的示例：`SmartObjectLayer.smartFilters` 保存顺序，命令修改列表，渲染器缓存计算结果，属性面板及 `edit_add_smart_filter` / `edit_manage_smart_filter` 使用同一命令路径。

## 验证分层

就近 `*.test.ts(x)` 覆盖模块行为；`tests/` 覆盖跨模块流程；`integration/` 覆盖生产 GPU、真实 RAW、工作台与可选在线服务。原生测试通过 `scripts/run-cargo.ps1` 执行。自动测试通过后，桌面交互与真实照片质量仍需要对应实测。
